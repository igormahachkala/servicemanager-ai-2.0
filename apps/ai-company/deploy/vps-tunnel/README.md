# Панель AI Company снаружи — через тот же WireGuard, что у «Моего помощника»

Используется уже работающий туннель daily: VPS `10.77.0.1` ⇄ офисный Linux («красный») `10.77.0.2`.
Новых портов наружу не открывается, Cloudflare не нужен.

```
Браузер ──HTTPS + логин/пароль──▶ VPS nginx  https://<поддомен>
                                     │  proxy_pass http://10.77.0.2:18080
                                     ▼  (WireGuard)
                          офисный Linux nginx stream  10.77.0.2:18080
                                     │  только от 10.77.0.1
                                     ▼  (локалка)
                          Windows-сервер 192.168.1.157:8080  ── панель + Ollama
```

- Пароль проверяет VPS. **Без пароля сайт не публикуется**: скрипт в конце проверяет, что без него
  отвечает `401`, иначе сам выключает сайт. Своего входа у панели нет.
- Ollama панели наружу не выходит: браузер ходит к ней только через панель (`/runtime/ollama`).
- Ответ модели идёт потоком, буферизация на VPS выключена, таймауты 600 с.

## Порядок

**0. DNS (Cloudflare).** Запись `A`: поддомен (например `ai`) → публичный IP VPS. Облачко **серое**
(DNS only), иначе Let's Encrypt и длинные ответы пойдут через Cloudflare.

**1. Windows-сервер.** Шаги 01–04 из `windows-server/README.md`, панель открывается по `http://192.168.1.157:8080`.

**2. Офисный Linux** (там, где уже стоит туннель и nginx для Ollama):

```bash
sudo ./office_panel_forward.sh 192.168.1.157 8080
```

Добавляет `include /etc/nginx/stream.d/*.conf;` в существующий блок `stream {}` (с резервной копией
файла рядом), кладёт туда пересылку `10.77.0.2:18080 → 192.168.1.157:8080`, пускает только `10.77.0.1`,
открывает порт в ufw на интерфейсе туннеля, проверяет `nginx -t` и перезагружает nginx. Пересылку к
Ollama не трогает.

**3. VPS:**

```bash
sudo ./vps_panel_site.sh ai.sma-tech.ru you@mail.ru
```

Ставит nginx/certbot/htpasswd при необходимости, спрашивает пароль для пользователя `owner`
(другое имя: `PANEL_USER=igor`), создаёт сайт, получает сертификат Let's Encrypt, включает редирект
на HTTPS и проверяет, что без пароля — `401`.

Если порты 80/443 на VPS занимает не nginx (например, Docker с сайтом daily), скрипт остановится и
покажет процесс. Тогда сайт надо добавить в тот прокси — пришли вывод.

**4. Windows-сервер** (PowerShell от администратора):

```powershell
.\05-public-hostname.ps1 -Hostname ai.sma-tech.ru
```

Разрешает панели отвечать на это имя и перезапускает её. Если брандмауэр Windows не пускает
офисный Linux (профиль сети «Общедоступная»), добавь `-OfficeLinuxIp <IP красного>`.

Готово: `https://ai.sma-tech.ru`, вход — `owner` и пароль из шага 3.

## Проверки

| Где | Команда | Ожидается |
|---|---|---|
| офисный Linux | `curl -s -o /dev/null -w '%{http_code}' http://192.168.1.157:8080/` | `200` |
| VPS | `curl -s -o /dev/null -w '%{http_code}' http://10.77.0.2:18080/` | `200` |
| любой | `curl -s -o /dev/null -w '%{http_code}' https://ai.sma-tech.ru/` | `401` |
| любой | `curl -s -o /dev/null -w '%{http_code}' -u owner:ПАРОЛЬ https://ai.sma-tech.ru/` | `200` |

Сменить пароль: `sudo htpasswd /etc/nginx/ai-company.htpasswd owner`.
Добавить человека: `sudo htpasswd /etc/nginx/ai-company.htpasswd имя`.

## Частые проблемы

| Симптом | Что проверить |
|---|---|
| VPS: `curl 10.77.0.2:18080` → `000` | `sudo wg show` на обеих сторонах; на офисном Linux `sudo nginx -t`, `ss -ltn \| grep 18080` |
| Офисный Linux: `curl 192.168.1.157:8080` → `000` | служба `ai-company-web` на Windows, брандмауэр Windows (шаг 4 с `-OfficeLinuxIp`) |
| В браузере `Blocked request. This host is not allowed` | не выполнен шаг 4 на Windows |
| `502 Bad Gateway` на сайте | туннель или пересылка в офисе: проверки из таблицы сверху вниз |
| Ответ модели обрывается | `proxy_timeout 600s` в офисе и `proxy_read_timeout 600s` на VPS уже стоят; при более длинных ответах увеличить оба |
