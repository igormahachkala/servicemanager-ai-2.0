<!-- Общий файл: sma-deploy-stage и sma-deploy-prod.
     Механизм замка контура. Читается до шага, занимающего контур. -->

<purpose>
Замок контура. Не даёт двум агентам развернуть на один контур одновременно
и не даёт сбросить beta под задачей, которая ещё в приёмке.
</purpose>

<contour_lock>

<why>
Stage и Production обслуживают 4-6 агентов. До введения замка два агента
могли слить свои PR и развернуть подряд, не узнав друг о друге: сверка после
развёртывания проверяет вхождение своего кода, а не отсутствие чужого.
Тот же пробел мешал сбросу beta — предусловие смотрит теги stage-ok,
а задача, находящаяся в приёмке, тега ещё не имеет.
</why>

<mechanism>
Замок — тег в origin. Имя: stage-busy/&lt;ветка&gt; для Stage,
prod-busy/&lt;ветка&gt; для Production.

Имя тега содержит полное имя ветки вместе с типом: stage-busy/fix/push-fix,
не stage-busy/push-fix. То же правило, что у stage-ok, и по той же причине:
fix/push-fix и feat/push-fix иначе дают один тег.
</mechanism>

<why_tag>
Тег виден всем агентам сразу после git fetch, ставится одной командой
и не требует коммита. Занятие контура атомарно: git push существующего
в origin тега отклоняется, и второй агент получает отказ, а не тихую победу.
Файл в репозитории так не работает: его надо коммитить, а два коммита
в одну ветку не конфликтуют.
</why_tag>

<check>
Проверять занятость только по origin. Локальный список тегов устаревает:
чужой замок поставлен минуту назад и в вашей копии его нет.

git ls-remote --tags origin 'refs/tags/stage-busy/*'    # Stage
git ls-remote --tags origin 'refs/tags/prod-busy/*'     # Production

Вывод пуст — контур свободен.
Вывод содержит строки — контур занят, читать тело замка блоком read.
</check>

<read>
Чей замок и с каких пор:

git fetch origin tag &lt;имя замка&gt;
git tag -l --format='%(contents)' &lt;имя замка&gt;
git for-each-ref --format='%(creatordate:iso)' refs/tags/&lt;имя замка&gt;
</read>
<why_creatordate>
Возраст замка берётся из объекта тега, а не из поля date его тела. Тело
пишет сам агент: поле может отсутствовать, содержать местное время или
просто быть неверным. creatordate ставит git при создании тега.
</why_creatordate>

<acquire>
git tag -a &lt;префикс&gt;/&lt;ветка&gt; -m "Контур занят
branch: &lt;ветка задачи&gt;
pr: &lt;номер PR&gt;
agent: &lt;имя машины&gt; / &lt;кто ведёт задачу&gt;
date: &lt;дата и время UTC&gt;"
git push origin &lt;префикс&gt;/&lt;ветка&gt;
</acquire>
<agent_field>
Поле agent заполняется так, чтобы по нему можно было найти владельца:
имя машины — hostname — и человек либо задача, которая ведётся. Без этого
поле бесполезно: пользователь не поймёт, к кому идти, и единственным
исходом останется снятие замка.
</agent_field>
<on_push_rejected>
Отказ означает, что замок уже стоит: контур занял другой агент в промежутке
между вашей проверкой и вашей постановкой. Это штатный исход, а не сбой.
Свой локальный тег удалить — git tag -d &lt;имя&gt; — и остановиться,
как при занятом контуре.
</on_push_rejected>
<why_local_delete>
Локальный тег остался бы и попал в следующую проверку через git tag -l,
изобразив собственный замок там, где его нет.
</why_local_delete>

<release>
git tag -d &lt;префикс&gt;/&lt;ветка&gt;
git push origin :refs/tags/&lt;префикс&gt;/&lt;ветка&gt;
</release>
<release_order>
Снимать после того, как контур приведён в конечное состояние: на Stage —
после постановки stage-ok, в Production — после сверки и проверки критерия.
Снятый раньше замок пускает следующего агента на недоделанное.
</release_order>

<classify>
Наткнувшись на чужой замок, собрать факты и показать их пользователю
одним сообщением. Снятие в любом случае за пользователем, агент не решает.

Что собрать:
  имя замка и тело                git tag -l --format='%(contents)' &lt;имя&gt;
  возраст                         git for-each-ref --format='%(creatordate:iso)' refs/tags/&lt;имя&gt;
  ветка существует в origin       git ls-remote --heads origin '&lt;ветка из имени замка&gt;'
  состояние PR                    gh pr list --head &lt;ветка&gt; --state all --json number,state
  что развёрнуто на контуре       ssh sma 'cd &lt;workdir контура&gt; &amp;&amp; git rev-parse HEAD'
  входит ли ветка замка           git merge-base --is-ancestor origin/&lt;ветка&gt; &lt;вершина контура&gt;

<threshold contour="stage">4 часа</threshold>
<threshold contour="production">2 часа</threshold>
<why_threshold>
Порог не снимает замок и ничего не запрещает. Он меняет только формулировку
доклада: агент говорит «похоже на брошенный» вместо «контур занят».
Production занимают ненадолго, порог там ниже.
</why_threshold>

<case name="ветки нет в origin">
Замок мусорный: задача закрыта, ветка удалена, снимать замок было некому.
Ложных срабатываний здесь не бывает. Сказать прямо и предложить снять.
</case>
<case name="ветка есть, PR слит, возраст больше порога">
Похоже на брошенный: слияние прошло, а до снятия замка агент не дошёл.
Показать факты, назвать владельца из поля agent, предложить два пути —
найти владельца либо снять замок.
</case>
<case name="ветка есть, PR открыт">
Агент остановился между постановкой замка и слиянием. Контур при этом чист:
его код в beta не попал, снятие замка последствий не имеет. Самый безобидный
случай, но решение всё равно за пользователем.
</case>
<case name="возраст меньше порога">
Контур занят, идёт работа. Ждать. Ничего не предлагать.
</case>

<contour_state>
В докладе показывать и состояние контура: входит ли ветка замка в развёрнутую
вершину. Входит — код брошенной задачи лежит на контуре, и снятие замка его
оттуда не убирает: следующее развёртывание пойдёт поверх. Тогда решается
не только судьба замка, но и нужен ли сброс beta.
</contour_state>
</classify>

<foreign_lock>
Чужой замок агент не снимает по своему решению. Ни при каких обстоятельствах,
включая полную уверенность, что владелец о нём забыл.
Порядок: собрать факты блоком classify, показать пользователю, ждать команды.
Снятие выполняется только по явной команде и сопровождается блоком lock_void.
<why>
Снятие пускает следующего агента на контур, который может быть занят
по-настоящему. Признак «брошенный» — вероятностный, а последствия ошибки
приходятся на живого владельца.
</why>
</foreign_lock>

<lock_void>
<when>Пользователь распорядился снять чужой замок.</when>
<command>
git tag -a lock-void/&lt;ветка&gt; -m "Чужой замок снят
lock: &lt;имя снятого замка&gt;
owner: &lt;поле agent из тела снятого замка&gt;
age: &lt;возраст на момент снятия&gt;
reason: &lt;почему сочли брошенным&gt;
by: &lt;кто снял&gt;
date: &lt;дата и время UTC&gt;"
git push origin lock-void/&lt;ветка&gt;

git push origin :refs/tags/&lt;имя снятого замка&gt;
</command>
<order>
Сначала поставить lock-void, потом снять замок. Обратный порядок оставляет
промежуток, в котором контур свободен, а объяснения не существует.
</order>
<why>
Владелец, если он жив, вернётся и не найдёт своего замка. Без записи он
не отличит собственную ошибку от чужого вмешательства и может продолжить
работу на контуре, который уже занят третьим агентом.
</why>
<cleanup>
Тег lock-void снимает тот, кто его ставил, после того как владелец
объявился либо стало ясно, что не объявится. Удаление тега — вопрос
пользователю.
</cleanup>
</lock_void>

<own_lock_missing>
<when>Агент дошёл до снятия своего замка, а замка в origin нет.</when>
<action>
Остановиться. Не считать это мелочью и не продолжать работу на контуре.
Проверить, не снимал ли замок кто-то другой:

git ls-remote --tags origin 'refs/tags/lock-void/&lt;ветка&gt;'
git fetch origin tag lock-void/&lt;ветка&gt;
git tag -l --format='%(contents)' lock-void/&lt;ветка&gt;

Тег есть — замок сняли, причина в теле. Контур мог быть занят другим
агентом после снятия: проверить занятость блоком check и показать
пользователю обе записи.
Тега нет — замок исчез необъяснимо. Сообщить пользователю, дальше
не работать с контуром.
</action>
</own_lock_missing>

<on_acceptance_failure>
Приёмка не прошла. Замок не снимается и не удерживается по решению агента:
вопрос пользователю, два исхода — освободить контур либо удержать
до исправления. Умолчание, предлагаемое первым, — освободить: правило
очереди, не получилось и встаём заново. Удержание для срочного исправления,
когда ожидание очереди дороже занятого контура.
Решено 2 сентября 2026, В-01 реестра.
</on_acceptance_failure>

<not_covered>
<item>
Автоматического снятия брошенных замков нет и не планируется. Признак
вероятностный, решение остаётся за пользователем — блоки classify
и foreign_lock. Следствие: пока пользователь не ответил, контур занят.
</item>
<where>Реестр: _claude/tasks/git-flow/open-questions.md.</where>
</not_covered>

<limits>
Замок держит контур, а не ветку: два агента с разными ветками не развернут
одновременно, но замок не мешает третьему читать контур и не мешает
пользователю работать в интерфейсе.
Замок не действует на агента, который его не проверяет. Защита
договорная, техническая только в атомарности постановки.
</limits>

</contour_lock>
