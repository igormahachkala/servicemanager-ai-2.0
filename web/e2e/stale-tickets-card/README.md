# Браузерная проверка карточки «Заявки старше 10 дней»

Моков нет: нужен живой backend и база, потому что проверяются точный
счёт сервера (`board?olderThanDays=10`, `meta.matchingTotal`), видимость
и обновление по WebSocket. В CI набор не входит: playwright не числится
в зависимостях web.

Что проверяется (25 проверок):

- `/dashboard` (компьютер): карточка показывает 3, ведёт на
  `/board?olderThanDays=10`; на доске чип «Старше 10 дней: 3» и ровно три
  старые заявки — без свежей, выполненной и чужой компании;
- `/m` (телефон): быстрая карточка «3 незакрытых», счёт пришёл с сервера,
  по нажатию список ровно из трёх старых, повторное нажатие снимает фильтр, возврат из карточки заявки фильтр сохраняет;
- клиент принимает работу по одной из заявок → на компьютере, на доске
  и на телефоне 3 → 2 без перезагрузки, заявка уходит из списков;
- ✕ на чипе доски убирает фильтр;
- ошибок страницы нет.

Запуск (локальная одноразовая база, Stage и Production не трогать):

```sh
# backend на :3399 (CORS_ALLOWED_ORIGINS=http://localhost:5398), база с применёнными миграциями
IDS=($(TAG=qa DATABASE_URL=… node web/e2e/stale-tickets-card/seed.cjs))
(cd web && npx vite --port 5398 --strictPort) &
TAG=qa node web/e2e/stale-tickets-card/run.cjs <путь>/playwright-core "${IDS[@]}"
```

Каждый прогон — свой `TAG` (сид создаёт новых пользователей). Адреса меняются
через `STALE_API`, `STALE_WEB`, снимки — `STALE_SHOTS`. Вход ограничен
по частоте: для повторных прогонов поднять `LOGIN_RATE_LIMIT_MAX_ATTEMPTS`.
