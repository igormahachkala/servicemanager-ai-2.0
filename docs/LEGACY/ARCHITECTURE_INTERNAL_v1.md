2. Общая концепция продукта

ServiceManager.AI — SaaS-платформа для управления сервисными заявками и распределённой сервисной сетью.

Целевая аудитория:

Сервисные компании

Сети точек

Управляющие компании

Франчайзинговые сети

Стратегический ориентир: Hubex / Okdesk / Planado.

Мы строим не CRM для мастеров.
Мы строим платформу управления сервисной сетью.

7. Автоназначение

Если:

autoAssignEnabled = true

и существует техник с нужной специализацией:

→ заявка автоматически назначается.

Иначе:

→ статус NEW.

8. Claim-механика

Реализовано:

GET /tickets/available
POST /tickets/:id/claim

Техник:

Видит NEW заявки по своей специализации

Может забрать заявку себе

Это шаг к гибкой модели распределения.

9. Ограничение доступа

Для TECHNICIAN:

Видит только назначенные ему заявки

Не имеет доступа к чужим

Реализовано через фильтрацию по:

assignedTechnicianId
10. Стратегическое обсуждение: Роли vs Блоки
Проблема

Role-based модель плохо масштабируется.

Если добавлять роли под каждую комбинацию прав:

ROLE_SLA_MANAGER
ROLE_REPORT_VIEWER
ROLE_REGION_ADMIN
ROLE_FINANCE_MANAGER

→ возникает ролевой хаос.

11. Стратегическое решение

Перейти к гибкой системе:

Role + Permission Blocks

Роль — базовый тип пользователя.
Блоки — конкретные права.
