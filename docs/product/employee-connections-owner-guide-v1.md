# Employee Connections — Owner Guide V1

> Для Owner AI Company — без технического жаргона.

---

## Зачем это нужно

Цифровые сотрудники работают с GitHub, Cursor, Ollama, почтой и другими сервисами. Раньше для DEV приходилось править `.env` вручную. **Connections Center** позволяет подключать инструменты через интерфейс.

---

## Как выбрать сотрудника

1. Откройте **Employees** в мобильной консоли.
2. Выберите сотрудника (например, **Builder**).
3. Нажмите **Подключения** или перейдите в `/mobile/employees/ag-builder/connections`.

---

## Как добавить сервис

1. Нажмите **Добавить инструмент**.
2. Выберите сервис из каталога (иконка + описание).
3. Заполните настройки (URL, репозиторий, endpoint).
4. Введите ключ — он сохранится только в локальном trusted runtime, не в браузере.
5. Выберите **capabilities** (что сотрудник может делать).
6. Укажите окружение (**DEV** для локальной работы).
7. Нажмите **Сохранить подключение**.
8. Нажмите **Проверить соединение**.

---

## Как выдать права

При сохранении подключения вы отмечаете capabilities:
- **Builder + Cursor:** dispatch automation, reconcile result
- **Builder + GitHub:** read repo, create branch, draft PR (merge запрещён по умолчанию)
- **Builder + Ollama:** list models, inference

Не все capabilities включены автоматически — вы выбираете явно.

---

## Как проверить подключение

Кнопка **Проверить соединение** на карточке:
- **Ollama** — проверяет endpoint и список моделей
- **Cursor** — проверяет URL и наличие ключа (задачу не запускает)
- **GitHub local** — проверяет origin репозитория

Статус **Подключено** появляется только после успешной проверки, не после сохранения формы.

---

## Как отключить

- **Отключить у сотрудника** — убирает grant, connection остаётся у компании.
- **Disconnect** — удаляет connection и secret из trusted runtime.

---

## Что означает стоимость

| Статус | Значение |
|--------|----------|
| Входит в подписку | Можно использовать по правилам grant |
| Доп. расходы | Нужен approval Owner |
| Стоимость неизвестна | Автоматическое использование запрещено |

AI Company **не покупает credits** и **не меняет тариф** автоматически.

---

## Почему сотруднику может быть запрещено действие

- Подключение не создано
- Capability не выдана
- Нужна авторизация (OAuth ещё не завершён)
- Проверка health не прошла
- Нужен approval Owner
- Окружение не разрешено (например, PRODUCTION)

---

## Legacy настройки

Если раньше использовались `.env` / VITE_* переменные, система покажет подсказку **Legacy configuration detected** — создайте connection через UI и постепенно переходите на новый flow.

---

## Локальный запуск

```bash
npm --prefix apps/ai-company run connections:bridge
npm --prefix apps/ai-company run dev
```

Без bridge secrets не сохраняются — UI покажет предупреждение.
