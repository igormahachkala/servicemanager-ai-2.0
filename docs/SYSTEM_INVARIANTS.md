# SYSTEM INVARIANTS — ServiceManager.AI

Этот документ фиксирует инварианты системы.

Инварианты — это правила,
которые нельзя нарушать ни при каких обстоятельствах.

Если инвариант нарушен —
архитектура системы считается сломанной.


--------------------------------------------------

1. Multi-tenant инвариант

Каждая доменная сущность должна содержать:

companyId

Это фундамент архитектуры.

Без companyId невозможно гарантировать
изоляцию данных между компаниями.


Нельзя:

- создавать доменные таблицы без companyId
- писать запросы без фильтра companyId
- возвращать данные без проверки companyId


--------------------------------------------------

2. JWT инвариант

JWT является единственным источником
идентификации пользователя.

JWT должен содержать:

userId  
companyId  
role


Нельзя:

- передавать companyId через body
- доверять companyId из frontend
- использовать hardcoded user


--------------------------------------------------

3. Authorization инвариант

Каждый защищенный endpoint
должен проверять доступ.

Через:

Guard


Нельзя:

- обходить guards
- проверять права только на frontend


--------------------------------------------------

4. Permission модель

Система должна двигаться к модели:

PBAC (Permission Based Access Control)

Роль — это только базовый тип пользователя.

Конкретные права должны контролироваться
через PermissionBlock.


--------------------------------------------------

5. Controller инвариант

Controllers не содержат
бизнес-логики.

Controller:

- принимает запрос
- валидирует DTO
- вызывает service


Вся бизнес-логика
должна находиться в service.


--------------------------------------------------

6. Service инвариант

Service слой отвечает за:

- бизнес логику
- проверки
- работу с базой


Service не должен:

- зависеть от HTTP
- использовать Request напрямую


--------------------------------------------------

7. Prisma инвариант

Все операции с базой данных
происходят только через Prisma.

Нельзя:

- использовать raw SQL
- делать прямые DB подключения


--------------------------------------------------

8. Error handling инвариант

Ошибки должны использовать:

NestJS Exceptions.

Примеры:

BadRequestException  
UnauthorizedException  
ForbiddenException  
NotFoundException  


Нельзя:

throw new Error()


--------------------------------------------------

9. Event Store инвариант

Каждое значимое действие системы
должно записываться как Domain Event.

Примеры событий:

ticket.created  
ticket.claimed  
ticket.status_changed  


Это позволяет:

- строить аналитику
- восстанавливать историю
- делать audit log


--------------------------------------------------

10. Ticket ownership инвариант

Техник может работать
только со своими тикетами.

Проверка должна происходить
на backend.


--------------------------------------------------

11. Security инвариант

Нельзя хранить:

- JWT токены
- пароли
- секреты

в коде.


Все секреты должны храниться:

.env  
docker secrets  
secret manager


--------------------------------------------------

12. File storage инвариант

Файлы не должны храниться
в базе данных.

Использовать:

object storage.


--------------------------------------------------

13. API contract инвариант

API должен быть:

backward compatible.


Нельзя:

- менять response format
- удалять поля
- ломать существующие endpoints


--------------------------------------------------

14. Migration инвариант

Изменения базы данных
делаются только через Prisma migrations.

Нельзя:

- изменять базу напрямую
- использовать prisma db push
в production.


--------------------------------------------------

15. Logging инвариант

Production код
не должен использовать:

console.log


Использовать:

NestJS Logger.


--------------------------------------------------

16. Архитектурная цель

ServiceManager.AI должен оставаться:

- модульной системой
- масштабируемой SaaS платформой
- безопасной multi-tenant архитектурой


--------------------------------------------------

17. Главный принцип

Если изменение нарушает
любой из этих инвариантов —

его нельзя принимать
в кодовую базу.
