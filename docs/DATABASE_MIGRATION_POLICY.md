# DATABASE MIGRATION POLICY — ServiceManager.AI

Этот документ описывает правила изменения базы данных
для проекта ServiceManager.AI.

Цель документа:

- предотвратить потерю данных
- обеспечить безопасные миграции
- сохранить совместимость между версиями
- поддерживать устойчивую SaaS архитектуру


--------------------------------------------------

1. Общий принцип

База данных является критической частью системы.

Любые изменения schema.prisma должны проходить
через контролируемые миграции.

Нельзя:

- менять структуру таблиц напрямую
- удалять поля без обсуждения
- менять типы колонок без анализа данных


--------------------------------------------------

2. Единственный источник истины

schema.prisma является единственным
источником структуры базы данных.

Все изменения делаются только через:

Prisma migrations.


Команда:

npx prisma migrate dev --name migration_name


--------------------------------------------------

3. Именование миграций

Название миграции должно описывать изменение.

Примеры:

add_ticket_sla  
add_permission_blocks  
add_domain_events  
add_ticket_status_history  

Плохие названия:

update  
fix  
test


--------------------------------------------------

4. Процесс изменения БД

Процесс всегда одинаковый:

1. изменить schema.prisma

2. проверить связи

3. создать миграцию

npx prisma migrate dev --name migration_name

4. проверить SQL файл миграции

5. протестировать систему


--------------------------------------------------

5. Проверка связей

Перед созданием миграции необходимо проверить:

- foreign keys
- unique constraints
- cascade правила
- nullable поля


Особенно важно для:

multi-tenant архитектуры.


--------------------------------------------------

6. Multi-tenant правило

Все доменные таблицы должны содержать:

companyId


Это обеспечивает:

изоляцию данных между компаниями.


Исключения:

- PermissionBlock
- системные таблицы


--------------------------------------------------

7. Удаление полей

Удаление колонок — опасная операция.

Перед удалением необходимо:

1. убедиться что поле не используется
2. удалить использование в коде
3. выполнить миграцию
4. протестировать систему


--------------------------------------------------

8. Добавление колонок

Добавление новых колонок должно быть:

backward compatible.


Пример безопасного добавления:

1. добавить nullable колонку
2. обновить код
3. постепенно заполнить данные


--------------------------------------------------

9. Индексы

Индексы должны добавляться
для часто используемых запросов.

Особенно для:

companyId  
ticket status  
assignedTechnicianId  
createdAt  


Пример:

@@index([companyId])

@@index([companyId, status])


--------------------------------------------------

10. Изменение типов колонок

Изменение типа может привести
к потере данных.

Перед изменением необходимо:

- проверить существующие данные
- убедиться в совместимости


--------------------------------------------------

11. Production миграции

В production используется команда:

npx prisma migrate deploy


Нельзя:

использовать prisma db push
в production.


--------------------------------------------------

12. Rollback стратегия

Prisma не поддерживает
автоматический rollback.

Поэтому:

каждая миграция должна быть
обратимой.


--------------------------------------------------

13. Seed данные

Для системных таблиц
используется seed.

Примеры:

PermissionBlock  
RolePermission  


Команда:

npx prisma db seed


--------------------------------------------------

14. Тестирование миграций

После каждой миграции необходимо проверить:

- создание пользователя
- создание тикета
- назначение техника
- board endpoint
- auth login


Это предотвращает
скрытые ошибки.


--------------------------------------------------

15. Архитектурная цель

База данных должна оставаться:

- стабильной
- масштабируемой
- безопасной

ServiceManager.AI — SaaS система,
поэтому структура БД должна быть
готова к росту количества компаний
и заявок.


--------------------------------------------------

16. Главный принцип

Любое изменение базы данных
должно быть:

предсказуемым
обратимым
и безопасным.
