# Пакет для нейросети Игоря

Два дела: изучить порядок работы и выполнить настройки, которые может
сделать только владелец репозитория и root на сервере.

---

## Состав

Всё лежит в репозитории, в ветке `docs/skills-flow-001`.

| файл | что это |
|---|---|
| `docs/draft/skills/01-настройки.md` | что выполнить. Три раздела: GitHub, доступ агентов, сервер |
| `skills/git-workflow.md` | ветвление и работа над задачей |
| `skills/agent-setup.md` | подготовка машины агента: ssh и gh |
| `skills/secrets.md` | переменные окружения и секреты |
| `skills/deploy-stage.md` | проверки, PR в beta, развёртывание на Stage, приёмка |
| `skills/deploy-prod.md` | проверки, PR в prod, развёртывание в Production, откат |

Пять файлов лежат именно в `skills/`, в корне репозитория: ссылки внутри
них записаны этим путём. Перенос в другой каталог сломал бы их все.

---

## Что изменилось в проекте

Введён ствол. Ветка `prod` соответствует коду, работающему в Production,
ветка `beta` — коду на Stage. Задача проходит один маршрут:

```
ветка от origin/prod → PR в beta → приёмка на Stage → PR в prod → развёртывание
```

Оба контура переехали на постоянные каталоги: `/opt/sma-prod` и `/opt/sma-beta`.
Каталоги с именами по релизам больше не используются.

Заведён пользователь `deploy` для развёртывания. Работа под root в потоке
не предусмотрена.

**Причина.** Production однажды работал на коде, отсутствующем в GitHub: три
коммита от 19 августа доставили на сервер через git bundle. Установить,
что именно работает у пользователей, удалось только сверкой строк внутри
собранного JavaScript. Ствол и эти skill — ответ на тот случай.

---

## Порядок

1. Прочитать `skills/git-workflow.md` целиком — он короткий и задаёт рамку.
2. Выполнить `01-настройки.md`, раздел за разделом.
3. Прислать вывод проверок из каждого раздела.
4. Остальные skill читать перед первой задачей, а не сейчас: они устроены
   как порядок исполнения, а не как обзор.

---

## Чего не делать

Не править `skills/` напрямую. Изменение правил идёт тем же потоком,
что любой код: ветка от `origin/prod`, PR, приёмка. Порядок описан
в самих файлах.

Не выполнять развёртывание по этим файлам, пока не выполнен раздел 2
`01-настройки.md`: без токена с нужными правами поток остановится
на создании PR.
